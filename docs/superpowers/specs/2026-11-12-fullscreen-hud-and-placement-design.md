# 파도마을 v0.3 · 화면 가시성과 건설 피드백

## 목적
사용자가 지도를 보는 공간을 상단의 전폭 고정 헤더에 빼앗기지 않게 하고, 첫 건설 전에 길 연결 상태를 이해할 수 있게 한다. 사용자는 아이디어 선택을 포함한 판단을 개발자에게 위임했다.

## 현상과 원인
- 데스크톱 1365×820에서 전폭 헤더가 높이 75px을 소비하고 캔버스는 y=75부터 시작했다. 모바일 390×844에서도 헤더는 63px을 소비했다.
- 지도 상 건설 미리보기는 지면 여부·점유만 확인한다. 자원 부족과 항구 연결 가능 여부를 건설 전에는 알 수 없다.

## 접근 비교
1. 기존 헤더 축소만: 변경은 적지만 화면을 가로질러 지도 공간을 계속 소비한다.
2. 헤더 전체 숨김: 시야는 확보되지만 일수, 일시정지, 도움말을 찾기 어려워진다.
3. **선택: 풀스크린 지도 + 양 모서리의 작은 반투명 헤더 그룹.** 헤더 아래의 지도는 계속 그려지고, 자원·배달·도구를 겹치지 않게 위치시킨다.

## 요구 및 비목표
- 지도 캔버스는 화면 전체 높이. 헤더는 배경 없는 오버레이이고 조작 가능한 하위 컨트롤에만 포인터가 닿는다.
- 1365×820, 390×844, 360×740에서 상단 컨트롤, 자원, 배달 버튼, 도구가 겹치지 않아야 한다. 일시정지·배속·도움말 유지.
- `evaluatePlacement(game,type,x,y)`가 무변경으로 건설 가능, 코인/목재 부족, 연결 가능 여부를 알려주고 `place`와 지도 미리보기가 같은 기준을 사용한다.
- 건설 선택 시 유효한 연결 위치는 청록, 연결되지 않은 위치는 황금, 무효는 붉은색으로 표시. 길 모드에서 항구와 연결된 도로는 약한 표시만.
- 저장 포맷, 경제, 건설 비용, 업그레이드 시스템, 그래픽 아틀라스 규격은 변경하지 않는다.

## 검증
- 기존 모델/렌더 테스트+새 placement 테스트 통과
- 실제 Chromium에서 세 뷰포트의 DOM 사각형, 실제 메뉴 사용, 건설/배달/저장, JS 오류 및 캡처 확인
- 묶음 커밋 1회 + 해당 커밋의 배포 상태 확인
