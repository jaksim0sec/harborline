# 파도마을 · HARBORLINE

> 바다 건너 편지가 도착하면, 작은 마을이 하루씩 자랍니다.

**단독 AI 주도 개발 실험의 첫 플레이 가능한 버전 (`v0.5.0`)**입니다. 다운로드나 서버 없이 브라우저에서 실행되는 따뜻한 2.5D 경영 게임을 목표로 합니다. 특정 게임의 그래픽·캐릭터·UI를 복제하지 않습니다.

## 해보기

`index.html`을 열거나, 리포지토리를 정적 웹 서버로 서빙하세요. 별도 설치·외부 API·계정은 필요하지 않습니다.

```sh
python3 -m http.server 5173
# http://localhost:5173
```

GitHub Pages를 쓰려면 저장소 **Settings → Pages → Deploy from a branch → main / (root)**로 설정하면 됩니다. Pages 활성화 여부는 별도로 확인해야 합니다.

## 플레이 방법

1. 밭이 햇밀을, 나무 공방이 목재를 생산하고 빵집이 햇밀을 빵으로 바꿉니다. 시간 ×2도 지원합니다.
2. 아래 건설 도구에서 길·밭·공방·빵집·집·꽃마당을 골라 건설합니다. 생산 건물은 **항구까지 연결된 산책길의 옆에 있어야** 작동합니다.
3. 오른쪽 **✉ 배달** 버튼에서 편지 목록을 열고 물건을 배달하면 코인과 마을 온기를 받습니다. 배달 6회를 달성하면 첫 바다 축제를 엽니다. 이후 자유롭게 이어갈 수 있습니다.
4. 건물을 눌러 연결 상태를 확인하거나 철거하고 일부 비용을 돌려받습니다. 저장은 브라우저 `localStorage`에 자동으로 남습니다.

**조작:** 마우스 또는 터치로 드래그 이동, 스크롤 또는 지도 +- 확대, 두 손가락 핀치, 숫자 1~7 건설 선택, `Esc` 배달 목록 닫기 또는 선택 해제, `Space` 일시정지.

## 기술 선택과 최적화

| 구분 | 구현 |
|---|---|
| 시뮬레이션 | 순수 JS 데이터 모델, 경로 BFS, 고정된 하루 주기. DOM·렌더러와 분리 |
| 투영 | 전 오브젝트 동일한 2:1 등각 투영 좌표계 |
| 텍스처 | 도형을 매 프레임 그리지 않고 **첫 로딩 시 텍스처 아틀라스에 한 번 래스터화**하고 그 후 `drawImage`로 재사용 |
| 지도 | 한 장의 캐시된 맵 레이어. 건설·철거 때만 캐시 무효화 |
| 화면 | 게임 본체는 최대 30fps, DPR은 최대 1.75로 제한. 모바일에서 자동 축소 |
| 저장 | 버전이 있는 브라우저 로컬 저장. 외부 DB 없음 |
| 배포 | 빌드 단계 없는 정적 파일. GitHub Pages 가능 |

> 대규모 월드/수천 개 객체까지 빠르다는 뜻은 아닙니다. 현재는 24×24 타일의 **작은 완성 루프**에 맞춘 구조입니다. 맵이 커지는 시점에 청크 캐시 및 화면 영역 컬링을 측정 기반으로 도입해야 합니다.

## 개발과 검증

```sh

npm run check
```

브라우저 E2E는 레이아웃·터치·캔버스 상호작용을 실제 Chromium에서 별도로 확인해야 합니다. 시뮬레이션 단위 테스트 통과만으로 시각 품질이나 실제 플레이를 보증하지 않습니다.

## v0.2 · 마을에 숨결 넣기

- 화면은 2.5D 등각 투영 지도와 **한 번 만든 텍스처 아틀라스**로 렌더링합니다. 건물, 나무, 산책길, 건설 도구의 미리보기는 같은 아트를 공유합니다.
- 초기 카메라는 항구·빵집 중심으로 잡고, 주민 두 명과 고양이가 연결된 길을 오갑니다. 정적 마을은 캐시로 보관합니다.
- 자원·배달·건설 UI의 밀도를 줄이고 모바일에서 첫 화면의 항구가 잘리지 않도록 구도를 조정했습니다.
- **아직 최종 아트 아님:** 배경·건물·인물은 프로시저럴 텍스처 프리비주얼이며, 주민 상호작용·사운드·게임 밸런스는 개발 진행 중입니다.

### 개발 확인

```bash
npm run check
python3 tests/browser_e2e.py # Chromium + Playwright 설치 환경에서 실행
```

정적 웹 배포이며 로그인·원격 저장을 요구하지 않습니다. 브라우저의 localStorage에 저장된 기존 v1 마을 데이터를 읽습니다.

## v0.2.1 · 지도 가림과 건물 접지 수정

- 바다 건너 온 편지 패널은 **기본 접힘**으로 바꾸고, 우상단의 `✉ 배달` 버튼으로 열며 `×`나 `Esc`로 닫습니다. 배달·축제 기능은 그대로입니다.
- 건설 도구는 미리보기와 명칭을 유지한 채 세로 길이를 줄였습니다. 작은 화면에서는 가로 스크롤로 모든 도구를 사용할 수 있습니다.
- 집·빵집·공방에 동일한 기단과 접지 그림자를 그려 발밑이 붕 떠 보이지 않도록 했습니다. 항구의 기존 부두 발판은 중복하지 않습니다.
- 시뮬레이션·저장 포맷 변경 없음. 실기기 GPU 성능과 장시간 플레이 검증은 아직 하지 않았습니다.

## v0.3 · 풀스크린 지도와 건설 전 피드백

- 상단 **전폭 고정 헤더(PC 75px / 모바일 63px)**를 제거했습니다. 지도는 화면 전체를 렌더링하고, 좌측 마을 이름과 우측 시간 컨트롤은 작고 투명한 오버레이 섬으로 남습니다. 자원과 배달 버튼은 겹치지 않도록 재배치했습니다.
- 건설 위치 미리보기: **청록 = 항구 연결 가능**, **황금 = 건설 가능하지만 산책길이 필요**, **빨강 = 건설 불가(점유·지형·자원)**. 길을 고르면 항구까지 이어진 기존 산책길에 작은 점이 표시됩니다.
- 건설 판정은 `evaluatePlacement()` 순수 함수로 통일해 미리보기와 실제 설치가 다른 답을 내지 않도록 했습니다. 경제·저장 모델은 변경하지 않았습니다.
- 모바일 카메라는 항구와 배가 화면에 들어오도록 조정했습니다.

### 검증 범위

`npm run check`, `python3 tests/browser_e2e.py`로 Node 모델 테스트, Chromium에서 PC·모바일 레이아웃·버튼·건설·철거·배달까지 검증합니다. 현재 작업 환경에서는 브라우저의 직접 HTTP URL 탐색이 차단되어 실제 공개 URL의 브라우저 테스트는 별도로 필요합니다.


## v0.4 · 움직이는 마을

- 이전 주민/고양이는 아틀라스 셀이 비어 실제로 보이지 않는 문제가 있었습니다. 캐릭터를 2:1 등각 투영 비율에 맞는 한 번 생성하는 텍스처로 채웠습니다.
- 주민은 **항구에서 현재 도로망을 통해 실제 작동 중인 건물까지 이어지는 최단 길**을 왕복합니다. 건설·철거로 길이 바뀌면 이동 경로를 다시 계산하며, 분리된 건물에는 주민을 배정하지 않습니다.
- 매일 생산 시 건물 위에 `+4 햇밀` 같은 일시적인 생산 배지가 나타납니다. 실제 생산·소비 결과를 모델이 이벤트로 제공하므로 단순 임의 연출이 아니며, 작동하지 않은 건물에는 배지가 뜨지 않습니다.
- 배달 성공 후에는 배가 바다 쪽으로 출항해 돌아옵니다. 기존 즉시 배달 및 보상 규칙은 유지했고, 실패한 배달은 출항하지 않습니다.
- 연출은 일시적 상태이고 저장 형식은 기존 `harborline.save.v1` / `version: 1`과 같습니다. 일시정지하면 움직임도 멈춥니다. 별도 패널을 추가하지 않았습니다.

**현재 한계:** 인물의 이동과 생산은 실제 마을 데이터에 연결된 **표현 계층**입니다. 물자를 손으로 옮기는 새로운 경제 제약을 추가한 것은 아닙니다. 게임성/성능의 장기 실측은 별도 검증이 필요합니다.


## v0.5 · 이웃이 도와주는 배달

- 배달 목록에서 편지 하나의 **도움 요청**을 선택하면, 해당 물건을 만드는 연결된 시설에 주민 한 명이 가서 일을 도와요. 다른 편지를 선택하거나 다시 누르면 언제든 바꿀 수 있어요. 선택은 의무가 아닙니다.
- 햇밀 또는 목재 집중 시 하루 +2개를 추가 생산합니다. 빵 집중 시 햇밀 3개가 더 남아 있어야 빵 2개를 추가로 구울 수 있어요. 기존 생산과 가격·배달 보상은 그대로예요.
- 연결된 시설이 없다면 보너스나 일하는 주민을 꾸며내지 않습니다. 선택한 편지를 배달하면 집중 작업은 자동 해제돼요.
- 선택 상태는 기존 `harborline.save.v1`의 선택적 `focusOrderId` 값으로만 보관합니다. 과거 버전 저장은 정상 로드되며 기본 생산량을 유지합니다. 별도의 화면·자원·복잡한 주민 배치 시스템은 추가하지 않았습니다.

**검증:** `npm run check`, `python3 tests/browser_e2e.py` (Chromium, HTML/JS 인라인 로딩으로 실제 인터랙션 테스트). 브라우저가 로컬/외부 HTTP 페이지 탐색을 차단하는 환경에서는 공개 URL 직접 접속 여부까지 보장하지 않습니다.

## v0.6 · 첫 5분의 목표가 보이는 배달

새로운 화폐나 튜토리얼 패널 없이 **기존 편지와 안내 UI**에서 선택의 결과를 볼 수 있습니다.

- 편지마다 현재 생산 속도로 **약 며칠 뒤 배달 가능한지** 표시합니다. `도움 요청`으로 실제 며칠을 줄일 수 있는지도 비교합니다. 계산은 `advanceDay()`와 동일한 규칙으로 복사된 마을 상태에서만 수행하며 저장 데이터를 바꾸지 않습니다.
- 첫 배달을 준비할 때는 도움 요청을, 재료가 준비되면 배달을, 작업 시설과 항구가 끊기면 길 연결을, 축제 후에는 자유로운 꾸미기를 안내합니다. **모든 선택은 선택 사항**이며 타이머·벌칙은 없습니다.
- 기존 안내 카드를 압축하여 PC에서는 행동 버튼과 함께, 모바일에서는 작은 읽기 전용 힌트로 표시합니다. 어느 화면에서나 기존 배달 버튼과 건설 도구를 그대로 사용합니다.
- **예상 일수는 약속이 아닙니다.** 건설·철거·집중 작업·재고 사용에 따라 바뀌며 최대 30일까지만 예측합니다. 미래의 지형 확장이나 새 자원은 계산하지 않습니다.
- 그래픽 후속 목표: 기존 초록의 채도와 식생 밀도를 보강하고, 주민은 큰 얼굴/짧은 팔다리의 일관된 테포르메 텍스처로 정비합니다. 섬 확장은 저장/청크/카메라 영향 검증 후 별도 단계로 진행합니다.

`harborline.save.v1`과 `version: 1`은 변함없으며, 새 필수 저장 필드는 없습니다.

## v0.7 · 푸릇푸릇한 섬과 동글한 이웃

- 2:1 고정 등각 투영의 사전 래스터 아틀라스에 초록 잔디·꽃 핀 풀밭·클로버 등 지형 변형을 추가했습니다. 정적 레이어에만 그리며 매 프레임 새 풀을 그리지 않습니다.
- 나무와 덤불을 잎과 명암이 읽히는 형태로 다시 그렸고, 이름만 존재하던 꽃무리·바위·등대·부두 말뚝 텍스처를 채웠습니다.
- 주민은 큰 얼굴·짧은 몸으로, 고양이는 큰 머리와 귀·눈으로 실루엣을 정돈했습니다. 접점과 아틀라스 크기는 유지했습니다.
- 이번 단계에서 `model.js`, 저장 키, 섬 크기, 생산·건설·배달 규칙을 수정하지 않았습니다. **섬 확장은 설계 영향만 기록**했습니다.

아트 검증: `npm run check`, `python3 tests/art_e2e.py`, `python3 tests/browser_e2e.py` (Chromium/Playwright 설치 환경). 24×24를 넘기는 확장에는 별도 저장 좌표 보존·청크 캐시·실성능 측정이 필요합니다.
